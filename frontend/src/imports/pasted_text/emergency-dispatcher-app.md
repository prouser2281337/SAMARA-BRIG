Общее описание и бизнес-логика проекта
Ты должен разработать систему, которая автоматизирует планирование работы мобильных ремонтных бригад. Система должна помочь диспетчеру эффективно распределять заявки от клиентов, оптимизировать маршруты и контролировать загрузку специалистов.

Ключевые сущности и процессы:

Бригады: Несколько мобильных бригад. Каждая бригада имеет фиксированный состав (2-3 специалиста), определенную квалификацию (например, "сантехники", "электрики", "универсалы"), и за ней закреплен служебный автомобиль.
База (Гараж): Единая точка старта и финиша для всех бригад. Здесь они начинают и заканчивают рабочий день, пополняют материалы.
Заявки: Запросы от клиентов. Каждая заявка содержит: адрес объекта, тип требуемых работ, желаемую дату/время визита и плановую длительность выполнения работ на месте.
Рабочий процесс бригады: Рабочий день (например, с 9:00 до 18:00) представляет собой замкнутый цикл: Гараж -> Объект 1 -> Объект 2 -> ... -> Объект N -> Гараж.
Ключевая проблема для решения: Главная задача — составить оптимальные маршрутные листы для каждой бригады на день. Оптимизация должна преследовать несколько целей:
Минимизация "холостых пробегов" (времени в пути между объектами). Для этого нужно группировать территориально близкие заявки.
Максимальное использование рабочего времени: Суммарное время (все работы + все перемещения, включая дорогу до первого объекта и обратно с последнего) должно укладываться в рамки рабочего дня.
Равномерная загрузка бригад.
Соблюдение временных окон, желаемых клиентами, по возможности.
Результатом работы системы для диспетчера должен быть готовый маршрутный лист для каждой бригады, где указано: время выезда из гаража, последовательность объектов, время прибытия, начала и окончания работ на каждом объекте, и время возвращения в гараж.

ЭТАП 3: Реализация алгоритма планирования

Это ядро твоего приложения. Алгоритм будет вызываться через эндпоинт POST /api/planning/run.

Оформи алгоритм как отдельный сервисный класс/модуль.

Входные данные для алгоритма:

Дата планирования.
Список всех необработанных заявок на эту дату (получить из БД).
Список всех доступных бригад (получить из БД).
Координаты базы (гаража) и всех заявок.
Допущение: Используй внешнее API для расчета времени в пути между двумя точками (например, OSRM, Google Maps API) или симулируй его на основе евклидова расстояния, если API недоступно.
Логика работы алгоритма (упрощенная версия для старта):

Получить все нераспределенные заявки на заданный день.
Для каждой бригады инициализировать ее текущее время (начало смены, 9:00) и местоположение (гараж).
В цикле while (пока есть нераспределенные заявки И у бригад есть свободное время):
a. Для каждой бригады найти "лучшую" следующую заявку. Критерии "лучшей":
i. Заявка соответствует квалификации бригады.
ii. Время в пути от текущего местоположения бригады (или предыдущего объекта) + время выполнения заявки + время возвращения на базу укладывается в остаток рабочего дня.
iii. Приоритет: заявка, до которой ехать ближе всего от текущего положения бригады.
b. Если для бригады найдена подходящая заявка:
i. Рассчитать время прибытия, начала и окончания работ.
ii. Создать запись в таблице Assignments.
iii. Обновить текущее время и местоположение бригады.
iv. Пометить заявку как "назначенную".
Повторять, пока все заявки не будут распределены или пока у бригад не останется времени.
Заявки, которые не удалось распределить, должны остаться в статусе "новая" для обработки диспетчером вручную.
Выходные данные алгоритма: Заполненная записями таблица Assignments для указанной даты.
